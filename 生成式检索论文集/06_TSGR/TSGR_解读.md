# TSGR 解读

## 论文信息

- **标题：** TSGR: Taobao Search Generative Retrieval（TSGR：淘宝搜索生成式检索）
- **机构：** 阿里巴巴淘宝天猫集团（Taobao & Tmall Group of Alibaba）、浙江大学（Shengyu Zhang）
- **作者：** Tianyu Zhan, Gui Ling, Tong Xiong, Kunhai Lin, Yang Wang, Kaixuan Zhang, Zhihong Chen, Yuliang Yan, Dan Ou, Shengyu Zhang, Haihong Tang, Bo Zheng
- **arXiv：** 2607.18796 [cs.IR]，v2（v1: 2026-07-21，v2: 2026-07-22）
- **发表信息：** arXiv 预印本（ACM 会议模板，尚未见正式会议信息）；TSGR 已在淘宝搜索生产环境全量部署
- **关键词：** 生成式检索、语义ID、商业价值建模

## 一句话总结

TSGR 是淘宝搜索的统一生成式检索框架：用 QP-SID 把"查询条件下的商业价值排序"直接编进语义ID 的第三层码本，再用一个与生成主干联合训练的价值感知排序模块（VRM）复用主干隐状态对候选打分，从而让**一个 0.5B 模型同时完成检索与预排序**，绕过传统级联架构中的独立预排序阶段，最终在线 A/B 取得 IPV +0.43%、交易笔数 +1.12%、GMV +1.64%，并已全量上线。

## 背景与动机

**级联架构的痛点。** 工业电商搜索传统上是"召回（多路检索）→ 预排序 → 排序"的级联流水线，检索与排序由多个独立模型承担。这带来两个问题：其一，检索阶段的召回目标（相关性/相似度）与最终业务目标（CTR/CVR/GMV）错位，检索不感知价值信号时，会把"语义合理但商业逊色"的候选送入下游，高价值商品在源头就被漏检或排后；其二，模型数量多、链路长，基础设施与维护成本高，且各阶段之间的分布差异会层层放大。

**生成式检索的机遇与缺陷。** 生成式检索（GR）训练一个自回归模型直接生成目标商品的语义ID（SID），把全库商品知识压进模型参数，天然支持端到端优化、免维护大规模倒排/向量索引，并缓解双塔模型的负采样偏差。OneRec、OneSearch 等系统已验证其工业可行性。但现有 GR 有两个与生俱来的缺陷：

1. **价值不敏感的 SID 构建**：RQ-VAE/RQ-KMeans 类方法只保持语义相似性，语义相近但价值悬殊的商品会被映射进同一 SID 邻域；且 SID 全局唯一、与查询无关——同一商品无论被什么查询触发都拿同一个 ID，无法体现"在不同搜索意图下价值不同"。
2. **价值无感知的候选排序**：GR 只能按束搜索的 token 生成概率排序，反映的是序列似然而非商业价值；且候选是推理时动态生成的，生成阶段无法预取商品边信息（价格、CTR 统计、卖家特征等）。

TSGR 的判断是：这两个缺陷必须**同时**在"表示"和"打分"两个层面解决，只做其一都会留下短板。

## 核心方法详解

### 1. 整体架构：一个模型 = 检索器 + 预排序器

TSGR 的三层 SID 码本总规模为 $32768\times8192\times8192$：前两层是"语义码本"（32768×8192），第三层是"效率码本"（总大小 8192，由 N 个并行分支组成）。生成主干为 Qwen2.5-0.5B，前两层用前缀树约束的束搜索（beam 400/400），第三层标准束搜索（beam 10000），最后 VRM 对候选重排序。关键设计哲学是**让价值信号贯穿"ID 分配 → 训练标签 → 候选打分"全链路**，而不是只在末端补一个打分器。

### 2. QP-SID：把价值排序编进语义ID（最核心的创新）

**(a) 语义码本：类目+聚类双先验。** 利用淘宝已有的商品特征构建天然层次"商品 ∈ 聚类 ∈ 类目"：类目嵌入由同类目商品嵌入平均得到（式 1），第一层直接用类目嵌入初始化（类目数 8100+ ≈ 码本 8192）；再对"聚类嵌入 − 类目嵌入"的残差做 RQ-KMeans 学第二层（式 2），最后把前两层合并成 32768×8192。两个先验：类目先验让 SID 最粗层继承平台 taxonomy（可解释、可扩展）；聚类先验保证同聚类商品共享相同 SID 前缀（同款/相似商品天然聚在一起）。

**(b) 效率码本：按价值排序分配 token 索引。** 第三层在每个聚类内部按"点击量"给商品排序（式 3：$\pi_0=\operatorname{argsort}_{i\in\mathcal{C}} s_0(i)$），高价值商品占据更靠前的索引。直觉：共享第三级 token 的商品会互相强化训练信号，靠前的索引在训练中被访问更频繁、在束搜索中优先被展开——**索引位置本身就是价值编码**，生成似然由此与商品价值对齐。

**(c) 查询感知并行排序：同一商品，多套 ID。** 全局点击排序仍是查询无关的。QP-SID 进一步利用"查询可切分成词项、商品属于聚类"这一结构，从查询-商品点击统计推断词项-聚类关系：每个聚类选出 top-3 代表词项（过滤覆盖率 >80% 的无判别力词项，式 4），在每个词项 $t$ 下按 $s(i,t)$（该词项下商品点击量）单独排序（式 5），于是每个聚类有 **1 个默认排序 + 3 个词项条件排序 = 4 套并行排序**。

**(d) 服务时如何选路。** 给定查询 $q$，抽其词项与聚类代表词项求交集，按词项-聚类共现点击量取最优词项 $t^*$（式 11），第三级 token 取 $\pi_{t^*}(i)$，无交集时退回 $\pi_0(i)$（式 12）。案例（附录 A.4）很直观："磁吸"词项下，标题含"磁吸"的手机壳即使全局点击不高也被排到前面；查询"百乐capless钢笔十代"同时命中三个词项时选 top-1 词项"capless"决定排序。**本质上这是把"每个查询意图一条价值排序通道"的思想从模型结构挪到了 ID 编码层。**

值得注意的负结果（4.3.1）：让模型自己学习"多路输出"（输入默认排序、标签用词项排序的变体）会导致 99.8% 输出塌缩到默认通道、前两层准确率反被拖累——所以最终方案是**由规则确定性地在 serving 侧选路**，模型只需在选定排序内生成，这换取了稳定性。

### 3. VRM：零额外编码成本的价值感知重排

为什么不能用独立预排序模型？论文给出的理由是**分布差异**：GR 在自己的检索分布上优化生成似然，预排序模型对全量多源候选池打分，两阶段目标与分布都不对齐。VRM 的做法是把预排序"长"在生成主干上，四个组件：

1. **商品表示** $v_k=[x_k;e_k;z_k]$（式 7）：离线特征表的商品边信息向量 $x_k$（多窗口行为统计/类目特征/卖家统计/查询-商品共现四类）+ 原始商品嵌入 $e_k$（补偿 SID 构建丢失的信息）+ SID 嵌入经 MLP 压缩的 $z_k$（式 6）。
2. **用户表示** $u$（式 8）：对主干隐状态 $H_u\in\mathbb{R}^{L\times D}$ 做均值池化 + MLP——**复用生成时已算好的隐状态，不增加编码开销**。
3. **用户-商品交互** $a_k=\text{CrossAttn}(v_k,H_u,H_u)$（式 9）：商品表示作为 query 对用户上下文做注意力，捕捉细粒度匹配。
4. **打分**（式 10）：$[\,a_k;u;v_k\,]$ 拼接后过三个并行 MLP 头输出 PV/CTR/CVR 分数，推理时按 $\hat y^{pv}\times\hat y^{ctr}$ 复合分重排。

直觉：PV×CTR 之所以是最佳排序分（消融验证），是因为它与 HR 目标同构；CVR 头参与联合训练（多任务正则）但推理时不用，去掉 CVR 损失影响也确实可忽略。

### 4. 训练策略：渐进式三阶段

- **Pre-SFT（多任务预训练）**：预训练 LLM 不懂 SID，先用五类子任务分维度"唤醒"能力（表 1）：编码（标题→SID）、个性化（画像+查询+行为→标题，唯一的自然语言输出任务）、检索（查询→SID）、协同（触发商品→SID）、推荐（画像+行为→SID）。全部任务打乱后以交叉熵联合训练，降低后续 SFT 的学习难度与数据需求。消融显示五个任务全部正贡献，检索任务贡献最大（与下游目标最贴近），全部联合训练 +5.76%。
- **SFT（会话级带权多正例）**：基于 Prompt Generation 框架（统一模板+可配置特征槽位，保证训练-服务一致）。一个搜索会话的 pay/click/pv/unpv 四层商品打包成一条样本，pay/click/pv 作多个正例标签（互加注意力掩码），权重 $w_{pay}>w_{clk}>w_{pv}$，具体取 (1,2,3)；生成损失为加权交叉熵（式 13）。VRM 同步联合训练，总损失 $\mathcal{L}=\mathcal{L}_{gen}+\lambda\mathcal{L}_{rank}$（式 15，$\lambda=1$），排序损失是三个 BCE（式 14）。listwise 式多正例显著优于 pointwise（HR@1000 0.7922 vs 0.7714）。
- **RL（GRPO，探索后弃用）**：以在线排序模型的 CTR×CVR 为奖励（式 16），加上离线 DPO 偏好对增强（防组相对归一化误伤 top-1000 边缘候选）与动态分层熵正则（只对未收敛 prompt 的 1–2 层加探索，式 17–18），累计仅 +0.52%，性价比不敌 VRM，最终未上线。这个"诚实的负结果"本身很有信息量：**在生成检索里引入价值信号，改 ID 与联合训练头，比改奖励函数更高效**。

## 训练与推理全流程

**训练**：2 亿+ 真实交互（两周）→ Pre-SFT 五任务混训 → SFT（QP-SID 动态标签 + 会话级多正例 + VRM 联合损失）→（可选 GRPO，未采用）。超参：AdamW，cosine lr 1e-4，batch 256。

**推理（线上，NVIDIA H20，延迟预算 65ms）**：查询+用户上下文 → 约束束搜索：第 1–2 层在预建前缀树上做前缀约束解码（beam 400/400，剪掉无效序列），第 3 层标准束搜索（beam 10000，按查询选定的词项排序通道解码）→ 每个生成的候选即时取回边信息、VRM 打分 → 按 PV×CTR 重排 → top-1500 直接进排序阶段，**跳过预排序**。部署形态是多路检索之外的独立新增通道（附录 A.2），全量服务数亿用户。

## 实验与关键结果

**设置**：训练数据为淘宝搜索两周 2 亿+ 用户交互，测试集取次日消息；主干 Qwen2.5-0.5B；三层码本 32768×8192×8192，beam [400,400,10000]；主指标 HR@1000（同束宽比较）。基线：FORGE（淘宝 140 亿交互基准的 SID 方案，末层 token 随机初始化）与传统预排序模型（检索后追加）。

**主结果（表 2）**：

| 类别 | 方法 | HR@20 | HR@100 | HR@500 | HR@1000 | HR@5000 |
| --- | --- | --- | --- | --- | --- | --- |
| SID | FORGE | 0.4328 | 0.5863 | 0.7207 | 0.7735 | 0.8604 |
| SID | QP-SID† | 0.4635 | 0.6235 | 0.7669 | 0.8177 | 0.8961 |
| 预处理 | Pre-SFT† | 0.4694 | 0.6340 | 0.7740 | 0.8222 | 0.8987 |
| 后处理 | 预排序模型 | 0.4248 | 0.6264 | 0.8112 | 0.8552 | 0.8771 |
| 后处理 | RL | 0.4659 | 0.6420 | 0.7857 | 0.8277 | 0.9027 |
| 后处理 | VRM (TSGR)† | 0.4586 | 0.6677 | 0.8250 | 0.8651 | 0.8953 |

读法：FORGE→完整 TSGR 的 HR@1000 从 0.7735 升至 0.8651（+9.16 个百分点，即摘要口径）。QP-SID 单项 +4.42 个百分点，证明"价值+查询条件排序编进 ID"本身就值这么多；VRM 再 +3.73 个百分点，与外挂预排序模型的 +3.30 相当甚至更好，且不像预排序模型那样损伤 HR@20/HR@100（预排序模型 HR@20 从 0.4694 掉到 0.4248）——**统一模型避免了级联的目标错位与分布断层**。

**关键消融**：

- **SID 设计（图 3、表 3/4）**：从"对 FORGE 候选做效率重排"到"效率直接编进 SID"收益跃升；四层码本并三层减少级联误差；输入输出 SID 排序不一致会破坏复制能力（HR@100 大跌）；辅助多路标签放大第三层梯度、99.8% 输出塌缩到默认路径——支撑"规则选路、模型单路生成"的最终设计。分布上，训练标签 76.8% 落在词项通道而行为序列仅 44.6%，模型输出 67.9% 走词项通道，说明模型确实学会了多通道检索。
- **VRM（图 4/5、表 10）**：PV×CTR 排序分最佳（与 HR 同构）；去掉商品嵌入灾难性退化（SID 量化丢信息，嵌入是必要补充）；去边信息主要伤 HR@20；交叉注意力换成均值池化或 EOS 表示只轻伤 HR@1000——可作延迟敏感场景的轻量档位。VRM 在 TencentGR-10M 公开数据上也验证了泛化（HR@500 0.0786→0.0794）。
- **训练策略（图 6、表 5）**：Pre-SFT 各任务全正贡献、联合训练最优；listwise 带权多正例稳定优于 pointwise。
- **RL（表 8）**：基础 RL +0.02%、DPO 增强 +0.39%、动态熵正则 +0.11%，累计 +0.52%——收益温和，未上线。

**在线 A/B**：淘宝搜索生产环境，1% 流量、连续 38 天，TSGR 单模型取代"检索+预排序"、top-1500 直送排序层：**IPV +0.43%、交易笔数 +1.12%、GMV +1.64%**，统计显著，已全量部署。注意交易类指标（+1.12%/+1.64%）明显高于浏览类（+0.43%），说明价值感知带来的收益集中在成交侧，与其设计动机吻合。

## 创新点与亮点

1. **价值信号编入 ID 本身**（QP-SID）：以往工作要么只做语义量化，要么在模型外补排序；TSGR 用"第三层 token 索引=价值位次"这一极简编码，让束搜索的展开顺序天然偏向高价值商品，且按查询词项维护多套排序，解决了 SID 查询无关的痼疾。
2. **检索与预排序的单模型统一**（VRM）：复用主干隐状态做用户表示、共享嵌入、与生成目标联合优化，几乎零额外线上成本（65ms 预算内）地消灭了一个流水线阶段；与"生成概率当排序分"的同行路线形成对照。
3. **诚实的工程权衡**：论文明确报告 RL 的有限收益与弃用决策、多路输出的塌缩负结果、轻量替代档位（均值池化/EOS），这些"失败档案"对从业者比成功曲线更宝贵。
4. **全链路业务对齐**：从 ID 分配（价值位次）→ 训练标签（查询条件动态标签）→ 多正例权重（pay>click>pv）→ 重排分（PV×CTR）→ 在线部署（绕过预排序），每个环节都显式编码业务先验。

## 局限性与开放问题

（前四点基于论文内容，后三点为个人分析）

1. **词项通道覆盖有限**：每聚类仅 top-3 代表词项、且过滤覆盖率 >80% 的词项，长尾查询或新词项无法命中通道，只能退回默认排序；词项-聚类统计依赖 30 天点击窗口，存在冷启动与季节性问题。
2. **效率码本的价值信号较单一**：排序依据是点击量（默认通道）与词项下点击量，未直接纳入价格、转化、退款率等更贴近 GMV 的信号；论文引用的姊妹工作（arXiv:2607.11392）暗示更完整的价值编码尚有空间。
3. **HR@20 上的折衷**：VRM 的 HR@20（0.4586）低于 Pre-SFT（0.4694），价值重排以牺牲少量头部精度换取整体池质量；对头部敏感的场景需谨慎。
4. **RL 收益有限的原因未深挖**：论文只给出"边际增益"的结论，奖励模型与生成分布的偏差、约束解码对探索的限制等机理分析不足。
5. **（个人分析）码本静态性问题**：QP-SID 的四套排序离线定期重建，爆款商品价值位次更新滞后于实时市场；能否在线增量更新码本而不破坏已训练模型的前缀语义，是开放的工程难题。
6. **（个人分析）可迁移性待验证**：方法强依赖"类目/聚类先验 + 查询可切词"的电商结构；内容型搜索（无明确类目体系、查询长尾化）中词项通道构造需要重新设计。
7. **（个人分析）单模型单点风险**：统一模型虽省了一个阶段，但检索与预排序的耦合也意味着单模型故障影响面更大，论文未讨论灰度、回滚与多模型冗余策略。

## 对研究与工业落地的启示

- **"改 ID"与"改损失"往往优于"加模块"**：本文最有效的两个杠杆（价值编进第三层 token、多正例带权损失）都不增加线上成本；而 RL 这种重型手段在强 SFT 基线上性价比有限——先榨干表示与监督信号的设计空间，再考虑 RL。
- **生成检索落地三件套**：可解释的层次码本（类目+聚类先验）、渐进式训练（Pre-SFT 唤醒能力→SFT 对齐任务）、约束解码+轻量重排的推理工程（前缀树、beam 分层、复用隐状态）——这套组合拳可直接迁移到其他大规模搜推场景。
- **一致性问题要贯穿训练与服务**：输入输出 SID 排序必须一致、prompt 模板训练服务同源（Prompt Generation）、规则选路替代模型多路输出——多个消融共同指向"生成式系统对一致性极其敏感"这一经验。
- **业务指标进离线指标**：HR@1000 与在线 IPV/交易/GMV 的改善方向一致，说明候选池质量评估应以"下游可转化性"为导向；预排序模型提升 HR@1000 却伤 HR@20 的反例也提醒：单一指标优化可能掩盖级联损伤。
- **小模型够用**：0.5B 主干 + 精心设计的 ID 与训练策略即可支撑数亿用户的搜索主链路，"架构与数据设计 > 参数规模"在工业 GR 中再次得到印证。
